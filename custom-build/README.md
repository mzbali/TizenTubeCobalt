# YouTube with instant remote speed controls

This fork adds a small Java activity and receiver to the **official v2.0.3 ARM
APK**. It compiles our Java sources; it **does not rebuild Chromium/Cobalt**.
The original native engine and original three DEX files remain unchanged.
Apktool repackages the manifest/resources, adds our fourth DEX and JavaScript
asset, and signs the APK with a local key.

## Behaviour

- YouTube button: -0.25x. Netflix button: +0.25x.
- Clamp the remote buttons to 0.25x–2x; briefly display the speed in the upper right corner.
- Change the video directly through Cobalt's existing evaluateJavaScript bridge.
- Save via the upstream settings command handler, keeping its cached setting,
  speed menu and next-video setting in sync.
- Key Mapper sends one explicit broadcast, with no menu macros or keyboard swap.
  The receiver accepts only SLOWER/FASTER and only affects our foreground activity.
- Package: `io.github.mzbali.tizentube`; app name: YouTube.
- Uses the user's existing `Pictures/Youtube.png` artwork.
- Installs separately from `io.gh.reisxd.tizentube.cobalt` for easy rollback.

The same module is also imported by that fork's regular userscript entry point.

before; our additional speed code is bundled locally and needs no Mac or server.
Updating upstream's main userscript can still affect compatibility.

Android build-tools 35.0.0 and Apktool 2.12.1. `build.py` accepts JAVA_HOME,
TV_TOOLS, TV_BUILD_TOOLS, TV_ANDROID_JAR and TV_APKTOOL overrides.

Outputs are in `custom-build/out/`. `keys/` holds the local signing key and
password, is excluded from Git, and must be retained securely for future updates.
The superclass declaration generated by the build is compile-only and is never
packaged; the real implementation is in the original APK.

## Updating and rollback

Both repositories have `origin` pointing at the personal fork and `upstream`
pointing at reisxd's original. Fetch upstream, inspect changes, then merge onto
`tv-speed-controls`; don't reset the custom branch. Build against a new engine
only after updating the pinned APK, hash and compile-time bridge contract.
No automatic merge or upstream APK auto-update is configured for our add-on.

To roll back, open the original TizenTube app and restore `keymaps-original.json`
via Key Mapper. The original app and its data have not been replaced.

This is an unofficial personal build, unaffiliated with YouTube or Google.
Upstream source and licenses remain in their respective forks.
